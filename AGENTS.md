# Repository instructions

## Source of truth

- Treat `data/instruments/*.json` and `data/vocabulary.json` as the maintained source data.
- Do not edit `dist/`; it is generated by `npm run build`.
- Do not treat web pages, AI output, provider data, or files in `suggestions/` as authoritative.
- Keep changes scoped to ticker metadata. This project does not provide market data, trading, portfolio management, or investment advice.

## Data rules

- Follow schema version `4.0.0` and the constraints in `docs/data-model.md`.
- Preserve stable instrument, industry, and tag IDs.
- Keep unknown values empty instead of inferring them.
- Every non-empty industry or ETF classification must retain valid source references.
- Only `review.status: reviewed` records are published.
- When reviewed content changes, set it to `needs_review` unless a new human review is recorded with an updated UTC timestamp.
- Update the vocabulary and all affected instrument references in the same change.
- Never apply a suggestion directly to source data without human review.

## Validation

Use Node.js 22+ and run the smallest relevant checks. Before completing a data or code change, run:

```sh
npm run validate
npm test
python3 -m unittest discover -s tests -p 'test_*.py'
npm run build
```

For maintenance UI changes, also run:

```sh
npm run test:web
```

Do not weaken schema, semantic validation, review transitions, or release integrity checks to make invalid data pass.

## Change quality

- Keep generated releases reproducible.
- Add or update tests when behavior changes.
- Do not commit credentials, tokens, private notes, generated `dist/` files, or dependency caches.
- Keep README documentation focused on current behavior; use Git history for removed features and past migrations.
